# CAF Release Archive

A static, searchable archive of the historical CodeAurora / Qualcomm Android release table.

**Pinned source snapshot:**  
https://web.archive.org/web/20220207223122/https://wiki.codeaurora.org/xwiki/bin/QAEP/release

## What this repository does

- On the first GitHub Actions run, downloads the pinned Wayback snapshot.
- Parses the original five-column release table into `data/releases.json`.
- Retains the downloaded source HTML at `archive/source.html`.
- Commits both imported files back to the repository.
- Builds a static website with year-sharded JSON.
- Deploys the site to GitHub Pages.

There is **no schedule and no automatic refresh**. Once `data/releases.json` exists, ordinary pushes reuse the committed dataset and do not contact Wayback.

## Setup

1. Create a GitHub repository and push these source files to the `main` branch.
2. Open **Settings → Pages**.
3. Under **Build and deployment → Source**, select **GitHub Actions**.
4. Open **Actions** and allow workflows if GitHub asks.
5. The first workflow run will import the snapshot, commit the source/data, build the site, and deploy it.

No local Python installation or manual import command is required.

## Import behavior

The workflow checks `data/releases.json`:

- If the file is absent or empty, it imports the pinned Wayback snapshot.
- If the file already exists, it skips the import and uses committed data.
- If import or validation fails, the workflow stops; it will not publish an empty or obviously incomplete dataset.

The import step uses:

```text
https://web.archive.org/web/20220207223122id_/https://wiki.codeaurora.org/xwiki/bin/QAEP/release
```

The `id_` modifier requests the archived page without the Wayback toolbar.

## Explicit re-import

To deliberately fetch and parse the pinned snapshot again:

1. Open **Actions → Import, build and deploy CAF Release Archive**.
2. Select **Run workflow**.
3. Enable **Re-download and re-parse the pinned Wayback snapshot**.
4. Run the workflow.

Re-import replaces the committed HTML and JSON only after the parser completes. Review the resulting Git commit if you need to audit changes.

## Local development (optional)

```bash
python -m pip install -r requirements.txt
python scripts/build_site.py
python -m http.server 8000 --directory site
```

Then open http://localhost:8000.

To run the one-time importer locally instead:

```bash
python scripts/import_snapshot.py
```

## Data schema

Each record contains:

```json
{
  "date": "February 07, 2022",
  "date_iso": "2022-02-07",
  "tag": "LA.QSSI.12.0.r1-06100-qssi.0",
  "chipset": "qssi",
  "manifest": "LA.QSSI.12.0.r1-06100-qssi.0.xml",
  "android_version": "11.00.00",
  "source_row": 1
}
```

The importer preserves source cell text and row order. It does not infer missing values or rewrite Qualcomm tags.

## Frontend

- Year filter
- Chipset filter
- Pagination
- No frontend framework or runtime service required
